# microSD カードの中身（サンプル）

**このフォルダの中身が、そのまま microSD カードのルートになります。**

```
microsd_sample/          ←  このフォルダが
   ├── scenarios/            ↓
   └── system/          ←  SD カードのルート

SDカード (E:\ など)
   ├── scenarios/       ←  ここへコピーする
   └── system/
```

`microsd_sample` というフォルダごとコピーするのではなく、
**中身（`scenarios` と `system`）を SD のルート直下に置いてください。**

---

## 入れ方

### USB で転送する場合

1. 本体を USB でパソコンにつなぐ
2. メニュー下段の **USB ボタン**を押す（アイコンが「切」表示に変わる）
3. パソコンにドライブとして見えるので、`scenarios` と `system` をコピー
4. もう一度 **USB ボタン**を押して戻す
5. 一覧が自動で読み直され、シナリオが並ぶ

> **USB を有効にしている間、本体はカードを読めません。**
> シナリオ一覧が空になりますが故障ではありません。USB を切れば戻ります。

### カードリーダーで入れる場合

SD を抜いてパソコンに挿し、ルート直下へコピーしてください。

## 中身

| パス | 内容 |
|---|---|
| `scenarios/<ID>/scenario.json` | シナリオ本体。**ファイル名は固定** |
| `scenarios/<ID>/thumbnail.png` | 一覧に出る絵。56×56 で表示。無ければ枠だけ出る |
| `scenarios/<ID>/images/bg/*.png` | 背景画像 |
| `scenarios/<ID>/saves/*.json` | セーブと栞。**本体が自動で作ります** |
| `system/settings.json` | 本体設定。初回起動時に自動で作られる |

**フォルダ名がシナリオIDです。** ASCII の英数字と `_` のみ、32文字以内にしてください
（日本語のフォルダ名は使えません。画面に出す題名は `scenario.json` の
`meta.title` に日本語で書きます）。

### 紹介シナリオ（`00_ayame_sample`）

案内役の「あやめ」が AYAME の機能を一巡します。
**横向き**（`meta.rotation: 1`）、立ち絵は右です。

| 章 | 出てくるもの |
|---|---|
| タイトル | 「はじめから」／「つづきから」。続きは `load` の失敗で分けている |
| 1 | 本文の枠・複数の枠・ページ送り・ルビ |
| 2 | 縦書きの枠。横書きと同じ画面に出る |
| 3 | 選択肢で答えを**変数に覚え**、あとの本文と分岐で使う |
| 4 | `beep` の音列 |
| 5 | 表情4種の差し替えと、立ち位置の移動 |
| 6 | `save`。タイトルの「つづきから」で読み込む |
| 7 | **`suspend`。`eyecatch` を出してから電源を切る** |
| 8 | `end` |

**7 章がこのシナリオの見どころです。** 電子ペーパーは電源を切っても像が残るので、
`suspend` の `image` に好きな絵を指定すると、**次に手に取るまでその絵が出たまま**
になります。中断のたびに作品の顔を見せられる、という仕組みです。

```json
{ "type": "suspend", "image": "eyecatch", "slot": 1 }
```

> **立ち絵は単一画像方式**（体・目・口に分けていない）なので、
> 表情を変えるたびに背景から描き直されます。
> そのとき見出しと名前の枠も消えるため、`chara` のあとに毎回描き直しています。
> レイヤー方式なら消えません（`00_yukkuri_sample` と `23_face` を参照）。

### 旧・紹介シナリオ（`00_yukkuri_sample`）

二人の掛け合いで AYAME の機能を一巡します。**横向き**（`meta.rotation: 1`）です。

| 章 | 出てくるもの |
|---|---|
| タイトル | 「はじめから」／「続きから」。続きは `load` の失敗で分けている |
| 1 | 背景と立ち絵、電子ペーパーの性質 |
| 2 | 縦書きの枠・ルビ・禁則処理。横書きと同時に出る |
| 3 | 立ち絵のレイヤー合成。目 5 種 × 口 5 種を**11 枚**で組む |
| 4 | 選択肢と分岐（クイズ）。外した回数を変数で数える |
| 5 | `checkpoint` → `save` / `suspend` |
| 6 | `end` |

**選択肢のボタンは本文の枠に重なります。** ボタンは画面の下から積むためです。
直前の本文はタップ待ちにして、読ませてからボタンを出しています。

> **こちらの立ち絵は東方 Project 由来の「ゆっくり」素材です。**
> 配布元の規約に従ってください。紹介シナリオを `00_ayame_sample` へ
> 移したのはそのためで、こちらはレイヤー合成の作例として残しています。

### 青空文庫からの読み物（`02_nekonojimusyo`）

宮沢賢治「猫の事務所」。`tools/make_scenario.py` が
青空文庫の HTML から作ったものです。**手で書いた部分はありません。**

| 見るところ | |
|---|---|
| 縦書きで画面いっぱいに組まれ、1タップで1画面ぶん進む（全 18 タップ） |
| ルビ（`｜繻子《しゆす》`）が親字の右に出る |
| 傍点が**圏点のルビ**として1文字ずつ振られる（「かま猫」） |
| **左へはらうと前のページに戻る**（右へはらうと進む） |
| タイトルで「つづきから」を選ぶと、**前回読んでいたページ**に戻る |
| 最後に奥付（底本・入力者・校正者）が出る |

栞は**1ページごとの `save`** で残しています。電源を切っても、
もう一度開いて「つづきから」を選べば続きから読めます。

戻れるのは `meta.back_swipe` を入れてあるからです。縦書きは右から左へ
進むので、紙の本と同じく**左へはらうと戻り**ます。直近 20 画面まで。

`fonts/book.vlw` を同梱しています（0.16MB）。内蔵フォントには
「炯」「竃」「繻」が無く、**そのままだと何も描かれない**ためです。
本文に出てくる 611 字だけを収めているので軽く済んでいます。

> **明朝ではなくゴシックで作ってあります。** 明朝は 18px だと
> 細い横線がラスタライズで落ちて読めません（`tools/README.md` を参照）。

元の HTML（`464_19941.html`）は出所が分かるよう残してあります。
再生には使いません。

### 中断と再開の試し方（`20_suspend`）

1. 第 2 章の選択肢で「ここで中断する」を選ぶ
2. しおり画面が出て**電源が切れる**（画面はそのまま残る）
3. 電源を入れ直すと、メニューの**最上段に「続きから」**が出る
4. 押すと**第 2 章の画面**に戻り、選択肢がもう一度出る

戻る位置は `checkpoint` コマンドが決めています。
`suspend` を書いた場所ではありません（`SCENARIO_SPEC.md` の `checkpoint` を参照）。

> **栞は一度使うと消えます。** 「続きから」を押した後にメニューへ戻ると、
> ボタンは無くなっています。

### シナリオ独自のフォント（`22_font`）

`fonts/maruminya_18.vlw` を同梱し、`meta.font` で指しています。
本文がドット系の書体で出れば効いています。メニューへ戻ると内蔵フォントに戻ります。

**このサンプルだけ 1.2MB あります。** フォントを丸ごと同梱しているためです。
容量が惜しければ、このフォルダごと消して構いません。

> **このフォントは縦書きの句読点が横向きに出ます。**
> 元の `x12y12pxMaruMinya.ttf` が縦書き用字形（`︑` `﹁` など）を
> 1 字も持っていないためで、作り直しても直りません。
> ドット系の書体を見せるためのサンプルなので、そのままにしてあります。
> 自分の作品で縦書きにするなら、収録のある書体を選んでください
> （`tools/README.md` に一覧があります）。

自分のシナリオで使う場合は `tools/make_font.py` で作ります。
本文に出てくる文字だけに絞れば、ずっと軽くできます。

```bash
python tools/make_font.py フォント.ttf --size 18 --charset 本文.txt \
    -o scenarios/my_story/fonts/story.vlw
```

### わざと問題を入れてあるもの

この2つは**正常に動かないのが正しい**サンプルです。

**`07_broken`** — 存在しないシーンへの `jump`、未定義の背景名、無い画像ファイルを含みます。
起動時のログに `SCENARIO` タグの警告が並び、**それでも起動は止まらない**のが期待動作です。

```
W (xxx) SCENARIO:   scene 'main': jump to undefined scene 'no_such_scene'
W (xxx) SCENARIO:   scene 'main': background 'undefined_name' is not in assets
W (xxx) SCENARIO: Validation found 3 issue(s). Loading anyway
```

**`12_metalast`** — `meta` をファイルの末尾に置いてあります。
一覧のタイトルは各 `scenario.json` の**先頭 4KB だけ**を読んで取り出しているため、
このシナリオは**題名ではなくフォルダ名が表示されます**。
これは仕様どおりの動作です（`SCENARIO_SPEC.md` の 3.1 を参照）。
サムネイルも置いていないので、枠だけが出ます。

## 自分のシナリオを作るには

1. `scenarios/` の下にフォルダを作る（ASCII の英数字と `_`）
2. `01_momotaro/scenario.json` をコピーして書き換える
3. `thumbnail.png` を 56×56 で置く（任意）

書式は [`../SCENARIO_SPEC.md`](../SCENARIO_SPEC.md) にまとまっています。
使えるコマンドの一覧と、まだ使えないものは 4 章の表を見てください。

> **`meta` はファイルの先頭付近に置いてください。** 後ろにあると
> 一覧にフォルダ名が出ます（`12_metalast` がその例です）。
